# Лабораторная работа №5. Вариант 16

Обе динамические библиотеки реализуют интерфейс из `src/lab5.h`:

| Функция | `impl1` | `impl2` |
| --- | --- | --- |
| `PrimeCount(A, B)` | Проверка делителей для каждого числа | Решето Эратосфена |
| `GCF(A, B)` | Алгоритм Евклида | Перебор делителей от меньшего числа до 1 |

### Сборка и запуск

Команды выполняются из каталога `lab_5`. Требуются CMake 3.15+ и компилятор C11.

#### Linux:

```sh
cmake -S . -B build-linux
cmake --build build-linux
cd build-linux/bin
./program1
./program2
```

#### Windows:

```powershell
cmake -S . -B build-windows
cmake --build build-windows
cd build-windows/bin/Debug
.\program1.exe
.\program2.exe
```

Открытие библиотеки, поиск функций и выгрузка описаны в общем `src/loader.h`. CMake выбирает `loader_linux.c` с POSIX API или `loader_windows.c` с Win32 API.

### Пример ввода-вывода

| Ввод | Результат |
| --- | --- |
| `1 10 30` | `6` |
| `1 1 1` | `0` |
| `2 48 18` | `6` |
| `0` | Только в `program2`: переключение на другую реализацию |

`program2` начинает с `impl1`

### Сравнение способов подключения

| | `program1` | `program2` |
| --- | --- | --- |
| Сборка | Линковщик записывает зависимость от `impl1` | CMake собирает обе библиотеки, но исполняемый файл с ними не линкуется |
| Загрузка | Системный загрузчик подключает `impl1` при запуске | Программа открывает файл и получает адреса функций через API ОС |
| Выбор реализации | Зафиксирован при линковке | Меняется по команде `0` |
| Ошибка загрузки | Запуск завершается ошибкой загрузчика | Программа сообщает ошибку. Если не удалось открыть новую библиотеку или найти функции, используется прежняя |
