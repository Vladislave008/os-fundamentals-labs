# Лабораторная работа №3 — Операционные системы

## Задача

Вариант 12: **наложить K раз медианный фильтр на матрицу целых чисел**, размер окна задаёт
пользователь. Обработка выполняется несколькими потоками ОС, лимит одновременно работающих
вычислительных потоков задаётся ключом запуска `--threads P`.

Программа написана на C (C11) под Linux/POSIX: `pthread_create`, `pthread_join`,
`pthread_mutex_*`, `pthread_barrier_t`, `clock_gettime(CLOCK_MONOTONIC)`.
Сборка — CMake, на Windows и macOS конфигурация прерывается с ошибкой.

## Как устроен параллельный прогон

Источник `src/pool.c`. Матрица режется на блоки из целых строк (`block_rows`, по умолчанию
`rows / (4P)`), блоки не пересекаются, поэтому гонки на запись в результат нет.

Все потоки, включая главный, работают по одному циклу:

```
пока не взяты все блоки текущей итерации:         // блок захватывается под мьютексом
    взять номер блока у общей очереди                ← pthread_mutex_lock / unlock
    применить медианный фильтр к строкам блока        // без мьютекса, блоки не пересекаются
барьер итерации: все блоки обработаны
переключить свои рабочие буферы a <-> b              // локальные переменные потока
```

* Мьютекс защищает общий набор блоков — счётчик взятых блоков `next_block`. Критическая секция
  короткая: только захват номера блока. Это и есть требуемое в задании «общее поле, к которому
  обращаются несколько потоков».
* `next_block` не сбрасывается между итерациями, а растёт сквозным: на итерации `iter` доступны
  блоки с номерами `[iter * total_blocks, (iter+1) * total_blocks)`, поэтому очередь одна на
  весь прогон, а не отдельная на итерацию.
* `pthread_barrier_t` на P участников — ровно один на итерацию: пока все блоки текущей итерации
  не обработаны, никто не читает результат предыдущей. Переключать буферы между барьерами не
  нужно, каждый поток меняет их у себя после барьера, поэтому общих указателей в структуре нет.
* Итерации считаются по двойному буферу `a`/`b`: на итерации один буфер читается, другой
  пишется, после барьера роли меняются. Исходная матрица `src` не изменяется, поэтому каждый
  повтор измерения стартует с одинаковых данных.
* `--threads P` — общий лимит вместе с главным потоком: создаётся не более `P − 1` рабочих
  потоков, при `P = 1` считает сам `main`, барьеры не создаются.
* `pthread_barrier_init` вызывается до создания потоков, участников ровно `P`, поэтому отдельного
  «стартового гейта» не нужно: все потоки стартуют сразу, барьер синхронизирует только границы
  итераций. Если поток создать не удалось — программа завершается с ошибкой (`die`).
* Время измеряется от начала создания потоков до конца последней итерации, то есть создание
  `P − 1` потоков входит в `T_P`.

## Замер времени

`clock_gettime(CLOCK_MONOTONIC)` от начала создания потоков до конца последней итерации:
`join` потоков и копирование результата в `dst` в измеряемый интервал не входят, создание
потоков — входят. Границы измерения одинаковы для всех P. `--repeat N` даёт N прогонов, в
таблице — минимум и медиана.

`S(P) = T₁ / T_P`, `E(P) = 100 · S(P) / P`.

## Ввод матрицы

Три источника, ровно один: `--input FILE`, `--manual`, `--random`. Размеры задаются ключами
`--rows`/`--cols` (для `--manual` их можно не указывать — тогда программа спросит).

В файле только целые числа, ровно `rows*cols` штук, без заголовка и комментариев; числа можно
переводить строками как угодно. Функции ввода возвращают `void`: при любой ошибке (файл не
открылся, чисел не хватило, вместо числа мусор) печатается сообщение и вызывается
`exit(EXIT_FAILURE)` — проверять в `main` коды возврата не нужно.

## Проверка результата

Фильтрация одного пикселя и обработка блока не зависят от разбиения на блоки и от числа
потоков, поэтому результат детерминирован. `--check` считает тот же результат последовательно
(`filter_run_serial`) и сравнивает его с параллельным; расхождение печатается как номер строки и
столбца вместе с обоими значениями, программа возвращает код 2. Проверка выполняется вне
измеряемого интервала.
